# oxzoo-vue-django

Official [ox](https://github.com/saurav-codes/vps-ctl) deploy example: a Django 5.2 LTS JSON-free text API and a Vue 3 single-page app on one Ubuntu VPS, where nginx serves the built SPA statically and proxies `/api` and `/health` to gunicorn. The backend greets you with a tag from runtime env, the frontend bakes the same tag in at build time, so one variable demonstrates both environment flows. Four catalog services — postgres, redis, a celery worker, and celery beat — turn the same repo into a multi-service deploy: beat fires a heartbeat task every 60s, the worker writes one row per beat to postgres, and `/api/stats` returns the row count.

## Stack

| Layer | Tool | Pin |
|---|---|---|
| Backend | Django | 5.2 LTS (exact pin in `pyproject.toml`) |
| App server | gunicorn | 23.x (exact pin) |
| Task queue | celery worker + beat | 5.x (exact pin), from the ox catalog, no hand-written worker processes |
| Database | PostgreSQL | host-shared via the `postgres@17` catalog service; `dj-database-url` parses `DATABASE_URL` |
| Broker | Redis | host-shared via the `redis@7` catalog service; `REDIS_URL` is the celery broker |
| Python manager | uv | `pyproject.toml` + `uv.lock` + `.python-version` (3.13) |
| Frontend | Vue 3 + Vite 5 | npm, exact pins in `package.json` |
| Web | nginx | serves `dist/`, proxies `/api` + `/health` |
| Deploy | ox | systemd + nginx from `ox.toml` |

## Environment flow

| Variable | When it is read | Where it is set |
|---|---|---|
| `GREETING_TAG` (backend) | at RUNTIME, `os.environ.get("GREETING_TAG")` per request | ox Environment editor (`/srv/ox/oxzoo-vue-django/env`) |
| `GREETING_TAG` (frontend) | at BUILD time, baked into the bundle via `envPrefix = ["GREETING_", "VITE_"]` | ox Environment editor, present when the `npm run build` hook runs |
| `DJANGO_SECRET_KEY` (backend) | at RUNTIME | ox Environment editor (example ships a placeholder default) |
| `DATABASE_URL` (backend + worker) | at RUNTIME | autowired by the `postgres@17` catalog service (the env's database is named after the project) |
| `REDIS_URL` (worker) | at RUNTIME | autowired by the `redis@7` catalog service, with the project's own database index |
| `CELERY_BROKER_URL` (worker) | at RUNTIME | falls back to `REDIS_URL` in `hello/settings.py`; set it only for a custom broker |

nginx (generated by ox) serves `dist/` with `try_files ... /index.html` (SPA mode) and keeps only the `[frontend].api_paths` prefixes, `/api` and `/health`, proxied to gunicorn on `127.0.0.1:9108`.

## Services

All four come from `ox.toml` `[[services]]` blocks (the catalog owns their packages, units, and credentials):

| Service | What it proves |
|---|---|
| `postgres@17` | real database work: the `[deploy] migrate` hook creates `hello_heartbeat`, and `/api/stats` counts rows in it |
| `redis@7` | the celery broker, scoped to this project's own index |
| `celery@5` | worker processes from the catalog (`app = "hello"`, `workers = 1`), never a hand-written `[[processes]]` block |
| `celery-beat@5` | the every-60s `hello.tasks.heartbeat` schedule, so beat is genuinely used |

## Deploy with ox

1. Paste the clone URL into the ox dashboard: `git@github.com:saurav-codes/oxzoo-vue-django.git`
2. Open the Environment editor and set `GREETING_TAG` BEFORE the first deploy (e.g. `GREETING_TAG=w2-07`). The build hook bakes it into the frontend, so it must exist before the first deploy. Optionally set `DJANGO_SECRET_KEY` there too. `DATABASE_URL` and `REDIS_URL` are autowired by the services; leave them out.
3. Press Deploy. ox installs Python deps with `uv sync --frozen` and frontend deps with `npm install` (repo-local, no global installs), builds `dist/`, runs `manage.py migrate` against the project's postgres database (real work now: it creates the `hello_heartbeat` table), then starts gunicorn, the celery worker, and beat.

## Expected output

With `GREETING_TAG=<your-tag>`, the page shows:

```
frontend: hello world oxzoo-vue-django_<your-tag>
backend: hello world oxzoo-vue-django_<your-tag>
```

`GET /health` returns `200 ok` and is used as the deploy readiness check. `GET /api/stats` returns `beats=<N>`, with N growing as the worker completes heartbeats against postgres. The worker journal (`journalctl -u ox-oxzoo-vue-django-celery.service -f`) prints one `heartbeat <id>: hello world ...` line per row it writes.

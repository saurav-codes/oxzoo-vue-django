# oxzoo-vue-django

Deployed with [ox](https://deploywithox.com): deploy a repo to your own server with one command, no Docker. [Docs](https://deploywithox.com/docs) · [Guide for this stack](https://deploywithox.com/docs/guides/django)

An [ox](https://deploywithox.com) deploy example: a Django 5.2 API on gunicorn with a Celery worker and beat, PostgreSQL, Redis, and a Vue 3 SPA built by Vite, deployed to your own Ubuntu server. systemd runs gunicorn, the worker, and beat; Caddy serves the built SPA with an `index.html` fallback while sending only `/api` and `/health` to Django.

## Stack

| Layer | Tool | Role |
|---|---|---|
| Frontend | Vue 3.5 + Vite 5 | SPA built to `dist/` from `client/` |
| API | Django 5.2 on gunicorn 23 | `/api/greeting`, `/api/stats`, `/health` |
| Jobs | Celery 5.6 worker and beat | a heartbeat task every 60 seconds |
| Services | PostgreSQL 18, Redis 8 | provided by ox from `[services]` |
| Python | 3.13 (`.python-version`), uv | `uv.lock` is committed |

## ox.toml

```toml
# Django + Celery worker and beat, postgres, redis, and a Vue 3 SPA.

[app]
start  = "uv run gunicorn hello.wsgi:application --bind 127.0.0.1:$PORT --workers 2"
health = "/health"

[static]
dir = "dist"
spa = true
api = ["/api", "/health"]

[build]
commands = ["uv sync --frozen --no-dev", "npm run build"]
migrate  = "uv run python manage.py migrate --noinput"

[workers]
worker = "uv run celery -A hello worker --loglevel=INFO --concurrency=1"
beat   = "uv run celery -A hello beat --loglevel=INFO --schedule=$OX_DATA_DIR/celerybeat-schedule"

[services]
postgres = {}
redis    = {}

[tools]
node = "24"
```

The repo has two languages, so `[build] commands` names both: `npm ci` is detected from `package-lock.json` and runs first. `[build] migrate` runs before traffic switches, and ox snapshots the database first. Beat keeps its schedule file in `$OX_DATA_DIR`, which survives deploys.

## Environment flow

- **Run time:** `hello/views.py` and `hello/tasks.py` read `GREETING_TAG`.
- **Build time (SPA):** `vite.config.js` sets `envPrefix: ["GREETING_", "VITE_"]`, so the Vue app reads `import.meta.env.GREETING_TAG` and Vite bakes it into `dist/`. Changing a variable with `ox vars set` redeploys, which rebuilds the SPA.
- **Provided by ox:** `DATABASE_URL` and `REDIS_URL` from `[services]`, and `PUBLIC_HOST`, which `hello/settings.py` uses for `ALLOWED_HOSTS`.
- **`DJANGO_SECRET_KEY`:** generated by ox on the first review.

## Deploy with ox

```sh
curl -fsSL https://deploywithox.com/install.sh | sh
ox login
ox new https://github.com/saurav-codes/oxzoo-vue-django
printf 'GREETING_TAG=demo\n' | ox review oxzoo-vue-django --from-file - --generate DJANGO_SECRET_KEY --wait
```

## Expected output

```
frontend: hello world oxzoo-vue-django_<GREETING_TAG>
backend: hello world oxzoo-vue-django_<GREETING_TAG>
```

`GET /api/stats` returns `beats=<N>`, with N growing every minute as the worker writes heartbeats to Postgres. `ox logs oxzoo-vue-django --process worker --follow` shows one `heartbeat <id>: hello world ...` line per row, and `ox celery oxzoo-vue-django worker` shows the Celery app.

## Local development

```sh
npm ci && GREETING_TAG=dev npm run build
uv sync
uv run python manage.py migrate      # SQLite when DATABASE_URL is unset
GREETING_TAG=dev uv run gunicorn hello.wsgi:application --bind 127.0.0.1:9108
GREETING_TAG=dev uv run celery -A hello worker --beat --loglevel=INFO   # needs a local Redis
```
